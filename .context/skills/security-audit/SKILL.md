# Security Audit

## When to Use
Activate this skill when performing security assessments or code reviews within the FiscalZen codebase to identify and remediate security vulnerabilities. This includes audits triggered by feature development involving authentication or authorization logic, dependency updates, integration with external governmental services (SEFAZ, NFSe), or prior to production deployments. The focus is on verifying adherence to OWASP Top 10 security principles, robust input validation, secure management of authentication tokens, and enforcement of strict authorization controls to protect sensitive fiscal data and maintain tenant isolation.

## Instructions
1. **Identify Key Security-Related Files:** Focus on critical modules managing authentication, authorization, and error handling:
   - `apps/api/src/plugins/auth.ts` (JWT handling, token generation, user/tenant ID extraction)
   - `apps/api/src/utils/errors.ts` (security-related error classes like `UnauthorizedError`)
   - `packages/nfse-client/src/types.ts` (credential types and validation)
   - Tools impacting authentication logic under `tools/` such as `apply-auth-hard-reset.mjs`, `apply-auth-manifestacao-fix.mjs`, `apply-auth-dev-ids-fix.mjs`
2. **Review Authentication Logic:**
   - Validate that the `generateToken` function produces secure JWTs with appropriate algorithms and short expiration times.
   - Confirm `authPlugin` properly verifies tokens and handles invalid tokens with safe error messages using `UnauthorizedError`.
   - Check that helper functions `getUserId` and `getTenantId` consistently enforce proper validation and extraction of claims without data leakage.
3. **Perform Input Validation Checks:**
   - Inspect all input points for user and tenant identifiers ensuring they are sanitized and type-safe to prevent injection and tampering.
   - Verify that all inputs hitting sensitive authorization logic undergo rigorous validation (e.g., Zod schemas, explicit checks).
4. **Conduct Authorization and Access Control Reviews:**
   - Ensure that every API route and service enforces strict authorization filters based on the authenticated user’s tenant and role.
   - Look for potential Broken Object Level Authorization (BOLA) risks, ensuring resources cannot be accessed across tenants.
5. **Scan for OWASP Top 10 Vulnerabilities:**
   - Particularly focus on Injection (NoSQL, SQL, XML), Broken Authentication, Sensitive Data Exposure, Broken Access Control, and Security Misconfiguration.
   - Use static code patterns and manual inspection on JSON web token management, error handling (avoid verbose error leaks), and input parsing.
6. **Check Integration and Credential Handling:**
   - Examine the usage and storage of digital certificates (A1), credentials (`NfseCredentials`), and secrets to confirm encryption at rest and in transit.
   - Assess scripts in `tools/` folder for safe handling of authentication resets and token regeneration.
7. **Document and Report Findings:**
   - Use the example table format to categorize findings by severity and suggest actionable remediation steps.
   - Highlight any missing controls, improper error handling, or insecure design patterns.
8. **Recommend Continuous Security Practices:**
   - Suggest implementation of logging and monitoring to capture suspicious authentication events.
   - Promote dependency audits and vulnerability scanning as part of the CI/CD pipeline.
   - Advocate for periodic security training for development teams focused on secure coding within the FiscalZen context.

## Examples
```markdown
## Security Audit: Authentication Module

### Scope
The audit focused on `apps/api/src/plugins/auth.ts` and associated helper modules managing JWT authentication and user identity extraction.

### Findings
| ID  | Severity | Issue                                                         | Remediation                                                        |
|------|---------|---------------------------------------------------------------|-------------------------------------------------------------------|
| S1   | Critical| JWT tokens generated by `generateToken` have no expiration defined | Add expiration (`exp`) claims with short validity to tokens       |
| S2   | High   | Input to `getUserId` lacks sufficient validation allowing malformed IDs | Enforce strict validation using Zod schema or regex checks        |
| S3   | Medium | Error responses expose internal details from `UnauthorizedError` | Mask error messages to avoid leaking stack traces or sensitive info|
| S4   | High   | Tools in `tools/apply-auth-hard-reset.mjs` handle tokens without securely wiping secrets from memory | Apply secure memory wiping and clear environment variables post-use|

### Recommendations
- Implement token expiration and refresh token mechanisms.
- Use Zod or equivalent schema validation throughout input pipelines.
- Refactor error handling to use generic messages and log detailed errors internally.
- Secure scripts handling credentials with encryption and zeroize secrets after processing.
```

## Guidelines
- **Use Secure Cryptographic Standards:** Ensure JWTs are signed using secure algorithms (e.g., RS256 or HS256 with a strong secret) and include expiration (`exp`) and issued-at (`iat`) claims.
- **Enforce Strict Input Validation:** Leverage Zod schemas or robust validation libraries consistently across the codebase for all incoming data, especially for user and tenant identifiers.
- **Implement Principle of Least Privilege:** Enforce tenant isolation in multi-tenant environments by validating all access at the service and API layers with tenant-bound authorization.
- **Avoid Sensitive Data Exposure:** Never expose detailed error stack traces or sensitive internal data in API responses; use sanitized messages and proper logging.
- **Conduct Regular Dependency Audits:** Use tools to scan dependencies for known CVEs and keep them up to date to mitigate vulnerabilities.
- **Secure Credential Storage and Handling:** Credentials including A1 certificates and API secrets must be encrypted at rest and handled securely in memory, with usage restricted to essential modules only.
- **Apply Multi-Factor Authentication (MFA) Where Feasible:** Especially for administrative or sensitive fiscal data access operations.
- **Use HTTPS Everywhere:** Enforce TLS for all data in transit, including API calls, web frontend communication, and external integrations.
- **Implement Logging and Monitoring:** Capture security-relevant events such as failed logins, token invalidations, and access control denials, with alerting configured.
- **Perform Automated and Manual Security Testing:** Incorporate static analysis and dependency scanning into CI pipelines, supplemented by regular manual code reviews focused on security.
- **Review and Secure Custom Scripts:** Scripts within the `/tools` directory that alter authentication states must be carefully audited and controlled to avoid introducing security gaps.
